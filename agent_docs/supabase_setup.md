# Supabase Backend Setup Runbook

One-time setup to flip the extension from mock data to a live Supabase backend. Run this in the Supabase dashboard (no CLI required).

## Prerequisites
*   A free Supabase account at https://supabase.com
*   The `clients` table schema **must** mirror the keys in `FIELD_MAP` (`content.js`) and the shape of `MOCK_CLIENTS` (`mock_clients.js`). If you rename a column here, you must update both files.

---

## Step 1 — Create the project
1. Sign in to Supabase, create a new project named `sticker-visa-db`.
2. Pick a strong database password (you won't need it for the extension; only for direct DB access).
3. Choose the region closest to Dhaka (Singapore `ap-southeast-1` is typical).

## Step 2 — Create the `clients` table
Open **SQL Editor → New Query**, paste, run:

```sql
create table public.clients (
  id              bigint generated by default as identity primary key,
  passport_number text not null,
  surname         text not null,
  given_name      text not null,
  dob             date,
  nationality     text,
  email           text,
  phone           text,
  created_at      timestamptz default now()
);
```

## Step 4 — Enable Row Level Security + read policy
**Why this matters:** the Supabase anon key ships inside the unpacked extension bundle. Anyone who installs the extension can read the key. Without RLS, anyone with that key can read or write to every row in `clients`. RLS + a read-only policy makes the table publicly **readable** but never **writable** via the anon key.

```sql
alter table public.clients enable row level security;

create policy "anon read clients"
  on public.clients
  for select
  to anon
  using (true);
```

> If `clients` ever holds genuinely sensitive PII (not the synthetic demo data above), tighten the policy further — e.g. join against an `analyst_assignments` table and gate `using (auth.uid() = analyst_id)`.

## Step 5 — Copy the project URL and anon key
**Project Settings → API**:
*   `Project URL` → copy
*   `anon` `public` key → copy

## Step 6 — Wire credentials into the extension
Edit `config.js`:

```js
export const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";  // the anon public key
export const USE_MOCK = false;                      // flip mock → live
```

Reload the unpacked extension in `chrome://extensions` so the service worker picks up the new module values.

## Step 7 — Verify
1. Click the toolbar icon. The popup status line should read `Backend OK (supabase) — 4 client(s) loaded`.
2. Open `sandbox.html` (or `sandbox-google.html`), pick any client, click Autofill.
3. Click **Dump Current Values** and confirm every form field is populated and `csrf_token` still reads `DO_NOT_OVERWRITE_ME`.

## Troubleshooting
| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `Backend error: Supabase HTTP 401` | Bad / mismatched anon key | Re-copy the `anon public` key from Settings → API |
| `Backend error: Supabase HTTP 404` | Wrong project URL or table not in `public` schema | Verify `SUPABASE_URL` and that the table is named exactly `clients` |
| `Backend OK (supabase) — 0 client(s) loaded` | RLS enabled but no policy, or policy excludes `anon` | Re-run Step 4 |
| Service worker not picking up new config | MV3 caching | Toggle the extension off/on in `chrome://extensions` |
